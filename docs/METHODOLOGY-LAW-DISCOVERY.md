# Methodology — discovering laws from structural contradiction (the deeper achievement)

What emerged across this work is not only MATRIYA; it is a **repeatable method for discovering
laws**. Note what we did NOT start from: not an idea, not a solution, not an architecture. We
started from a **structural contradiction** — and only after the contradiction was *forced* did
a principle appear. That order is the method.

## The cycle (FSCTM, as practiced)
```
1. Contradiction   state a structural impossibility (e.g. no entity can own value + conditions
                   + uncertainty + provenance + authority with a unique value)
2. Falsify         enumerate the candidate architectures and REFUTE them (survivability test);
                   do not choose — let only the survivor remain
3. N (principle)   write the principle the analysis FORCES — scoped to the studied domain,
                   stated as authority, kept falsifiable (no implementation)
4. L (law)         Statement · Principle · Boundary of validity · Falsifier
5. Design          only now: how to represent it
6. Implementation  only now: code
```

## Why it is strong
- **It cannot produce a pretty-but-empty law.** A law without a falsifier is rejected at step 4.
- **It cannot over-generalize.** Every principle carries a boundary of validity; wider claims
  are parked behind evidence (≥2 further domains, by observation not design).
- **It separates what looks true from what bears authority** — the same move whether the domain
  is a database, a coating, or a combustion mechanism.

## Where it applies beyond databases
The pattern "distinguish what is *seen* from what *bears the authority*" is domain-independent.
Candidate reuses (not claims): intumescent char (what is measured vs what controls fire
endurance), raw-material identity (label/CoA vs incoming evidence), formulation (recipe vs the
four formula layers). Each could be run through the same six steps.

## The one-line summary
> MATRIYA is becoming less a system and more a **methodology for turning structural
> contradictions into falsifiable engineering laws** — and the software is just its first
> instrument.

(Recorded as an observation about the method, not a claim that the method is universally
proven. Like every law here, it earns its scope from use.)
